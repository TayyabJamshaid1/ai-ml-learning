File Pointer:
The file pointer is like a bookmark that keeps track of where you are in the file. It tells Python the position from which the next read or write operation will start.

scenario 1: 

f = open("verify.txt", "r")

# Step 1: Initial pointer position
# [I] am a Tayyab\nTayyab is a good boy\nGood f0r you Taibi\nI am a new line to be added
#  ↑
#  pointer at position 0 (beginning)

data1 = f.readline()
# READ: "I am a Tayyab\n"
# Pointer moves to after the \n
# I am a Tayyab\n[T]ayyab is a good boy\nGood f0r you Taibi\nI am a new line to be added
#               ↑
#               pointer at position 15 (after first line)

print(data1)  # Prints: "I am a Tayyab" 
# The print() function adds its own newline!
# So you see: "I am a Tayyab" + [newline from print]
# But wait! data1 already had a \n at the end!
# So the actual output is: "I am a Tayyab" + \n (from data1) + \n (from print)
# = ONE EMPTY LINE!

data2 = f.readline()
# READ: "Tayyab is a good boy\n"
# I am a Tayyab\nTayyab is a good boy\n[G]ood f0r you Taibi\nI am a new line to be added
#                                     ↑
#                                     pointer at position after line 2

print(data2)  # Prints: "Tayyab is a good boy" + \n (from data2) + \n (from print)
# = ANOTHER EMPTY LINE!

data3 = f.readline()
# READ: "Good f0r you Taibi\n"
# I am a Tayyab\nTayyab is a good boy\nGood f0r you Taibi\n[I] am a new line to be added
#                                                         ↑
#                                                         pointer at position after line 3

print(data3)  # Prints: "Good f0r you Taibi" + \n (from data3) + \n (from print)
# = YET ANOTHER EMPTY LINE!

data4 = f.readline()
# READ: "I am a new line to be added" (NO \n at the end)
# I am a Tayyab\nTayyab is a good boy\nGood f0r you Taibi\nI am a new line to be added[]
#                                                                                   ↑
#                                                                                   pointer at end

print(data4)  # Prints: "I am a new line to be added" + \n (from print only)
# = NO EMPTY LINE! (because data4 doesn't have \n)

f = open("verify.txt", "r")

# ALL content is read at once
allRead = f.read()  # Pointer moves to END of file
print(allRead)      # Prints everything

# Now the pointer is at the END
# Any further read() will return empty string
# Any readline() will return empty string

data1 = f.readline()  # Attempts to read from END
print(data1)          # Prints: '' (empty string)

data2 = f.readline()  # Attempts to read from END
print(data2)          # Prints: '' (empty string)

f.close()

Real-World Example: The Difference Matters!
Let me show you why binary mode is essential:

python
import os

# Create a file with special characters
with open("test.txt", "w", encoding="utf-8") as f:
    f.write("Hello 世界 🌍\n")
    f.write("Line 2\n")

# READING IN TEXT MODE
print("TEXT MODE:")
with open("test.txt", "r", encoding="utf-8") as f:
    data = f.read()
    print(f"Type: {type(data)}")
    print(f"Content: {data}")
    print(f"Length: {len(data)} characters")

print("\n" + "="*50)

# READING IN BINARY MODE
print("BINARY MODE:")
with open("test.txt", "rb") as f:
    data = f.read()
    print(f"Type: {type(data)}")
    print(f"Content: {data}")  # Shows raw bytes
    print(f"Length: {len(data)} bytes")
    print(f"Decoded: {data.decode('utf-8')}")
Output:

text
TEXT MODE:
Type: <class 'str'>
Content: Hello 世界 🌍
Line 2

==================================================

Line 2
Notice: The text mode shows 16 characters, but binary mode shows 25 bytes! This is because some characters (like 世界 🌍) take multiple bytes in UTF-8 encoding.
